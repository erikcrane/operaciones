# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Generates PDF worksheets of math exercises (in Spanish) and emails them; a single web server shows one button per exercise. It unifies the former sister projects `/home/fran/proyectos/multiplicaciones` and `/home/fran/proyectos/divisiones` (left untouched; the migrated sheets were verified pixel-identical to theirs with the same random seed). More exercises will be added. Code, comments, identifiers, output and docs are all in Spanish — keep new code consistent with that.

## Commands

uv project with src layout (the user chose it deliberately: the package is installed into `.venv` by `uv sync`, so imports never depend on the cwd). Python 3.13 (`.python-version`, `requires-python >=3.13`); dependency `reportlab` pinned in `uv.lock`. No test suite, linter or CI.

```bash
uv sync                                          # create/refresh .venv and install the package
uv run operaciones multiplicaciones [3 6 9]      # -> multiplicaciones_DD-MM_HHhMM_YYYY_NNN.pdf in cwd
uv run operaciones divisiones -o x.pdf
uv run operaciones divisiones -e [a@x.com]       # also email it (-e repeatable; no address -> .env recipients)
uv run operaciones servidor -p 8000              # web UI (default port 80, used in Docker)
python -m operaciones ...                        # same CLI; the server uses this form
```

## Architecture

Everything lives in `src/operaciones/`. Core idea: **no `if ejercicio == ...` anywhere**. Each exercise is a subpackage whose `__init__.py` is its "ficha de identidad", and `ejercicios/__init__.py` holds the registry `EJERCICIOS = {clave: módulo}` (dict order = button order). The CLI subcommands, server routes, web buttons and per-exercise email config all derive from it. The `clave` is the CLI subcommand, the `/generar/<clave>` route, the PDF filename prefix, the server's `pdfs/<clave>/` subfolder and (uppercased) the `.env` recipients key prefix — lowercase ASCII only.

Interface every exercise `__init__.py` must define: `NOMBRE` (button label), `DESCRIPCION` (CLI help), `NOMBRE_REMITENTE` (themed sender display name; `""` → the `.env` one), `ASUNTO_EMAIL`, `TEXTO_EMAIL`, `anadir_argumentos(parser)` (own args; `-o`/`-e` are added by `cli.py`), `comprobar(args)` (validate before generating; raise `ValueError` → shown as `parser.error`), `crear_pdf(args, ruta_pdf)` (generate numbers, choose rotating item, build PDF, then save rotation state in the cwd). Adding an exercise = new subpackage + one registry line; nothing else changes.

- `cli.py` — argparse subparsers built from `EJERCICIOS` plus `servidor`. `ejecutar_ejercicio` order matters: validate `-e` addresses → `comprobar` → `preparar_envio(direcciones, clave, ejercicio.NOMBRE_REMITENTE)` (only with `-e`; reads `.env` before generating anything, so a broken config creates no PDF and consumes no rotation item) → `nombre_pdf_automatico(clave)` unless `-o` → `crear_pdf` → `enviar_pdf`. `__init__.main()` (the `operaciones` script entry point) and `__main__.py` both call `cli.main`.
- `comun/rotacion.py` — `elegir_sin_repetir(candidatos, fichero)`: random choice among candidates not yet in the JSON file; when exhausted a new round starts that never begins with the last one; returns `(elegido, salidas)`, saved by the caller with `guardar_salidas` only after the PDF exists. Unknown entries ignored, corrupt file = new round. Used by multiplicaciones (reference table, `tablas_salidas.json`, candidates `NUMEROS_VALIDOS`) and divisiones (header titles, `cabeceras_salidas.json`). Rotation files are runtime state in the cwd (next to the PDFs), gitignored.
- `comun/pdf.py` — shared PDF pieces: `registrar_fuente` (TTF paths are relative to the package dir, e.g. `"fonts/Fredoka-SemiBold.ttf"`; bold/italic mapped to the same file so `<b>` works), `documento_a4`, `parrafos_cabecera` (centered title at 1.6× + justified intro, either may be `""`), `nombre_pdf_automatico(prefijo, carpeta)` (NNN = highest existing + 1, never resets). Each exercise draws its own layout in its own `pdf.py` — layouts differ too much to unify.
- `comun/enviar_email.py` — SMTP (Brevo) via stdlib. Config read **only** from one file: `/run/secrets/operaciones_env` (Docker secret) if it exists, else `<project root>/.env` (`parents[3]` of the module; gitignored; template `.env.ejemplo`). Environment variables are deliberately neither read nor written. SMTP account and sender address (`REMITENTE` = operaciones@erikcrane.com) are common to all exercises (user's decision); recipients differ via `<CLAVE>_DESTINATARIOS` (fallback `DESTINATARIOS`), and the sender display name comes from each exercise's `NOMBRE_REMITENTE` constant in code (fallback: `.env` `NOMBRE_REMITENTE`). Never put credentials in code.
- `servidor.py` + `index.html` (both inside the package) — stdlib `http.server`. `GET /ejercicios` returns `{ejercicios: [{clave, nombre}], espera}`; the page builds the buttons from it. `POST /generar/<clave>` validates `clave` against `EJERCICIOS` (404 otherwise; never execute raw input), then runs `[sys.executable, "-m", "operaciones", clave, "-e"]` with cwd `CARPETA_PDFS/<clave>` (env var, default `./pdfs` resolved at import), timeout `LIMITE_SEGUNDOS`. One lock (409) and **one common cooldown** `ESPERA_SEGUNDOS` = 20 s for all exercises (user's choice), counted from the end of each run, success or not (429). Every JSON reply carries `espera`; the page disables all buttons with a countdown. Script stdout/stderr goes only to the server console / Docker log, never to the page.
- `ejercicios/multiplicaciones/` — 10 dog/pet-shop word problems; tables and factors only 2–9 (0, 1, 10 never appear). `generar.py`: `tabla_valida` (argparse `type=`), `tablas_pedidas` (dedupe, empty → all), `generar_lineas` + `fix_adjacent_dups`, `elegir_tabla`. `pdf.py`: statements from `situaciones.py` (`OBJETOS`/`RELACIONES`/`PLANTILLAS`, `validar_datos`; emojis appended only before the first `¿`), Twemoji PNGs in `emojis/` replacing emojis as inline `<img>` (`preparar_emojis` downloads missing ones from jsDelivr, pinned `jdecked/twemoji@17.0.3`; impossible in Docker since the package dir is read-only for uid 1000, so new PNGs must be fetched locally and committed), reference table `tabla_multiplicar_pdf` (`LEADING = TAMANO_TABLA * (2 - ALTURA_CIFRAS)`, zero vertical padding, to center digits; `KeepTogether`).
- `ejercicios/divisiones/` — 6 decimal divisions, Fortnite theme. `generar.py`: integers in hundredths (dividend 100,01–999,99, divisor 10,01–99,99, hundredths digit never 0), unique pairs; `validar_cabeceras` (titles are the rotation key, must be unique); `elegir_cabecera`. `cabeceras.py`: 100 `(titulo, texto)` headers (texts ≤ 7 lines in the PDF). `pdf.py`: Anton for title (always uppercased) and text, Fredoka for numbers; 2×3 grid filling the height left under the header, each cell a `DivisionCaja` flowable ("L" box at `POSICION_CAJA`).
- Fonts in `src/operaciones/fonts/` (Anton, Fredoka SemiBold static weight-600 instance; SIL OFL, licenses alongside). They, `emojis/` and `index.html` are inside the package so they ship in the wheel (uv_build includes them; verified).
- Docker: `Dockerfile` (python:3.13-slim + `uv` 0.13.6 binary; `uv sync --locked --no-dev --no-editable` into `/app/.venv`; `CMD ["operaciones", "servidor"]`) + `docker-compose.yml`: container `operaciones`, port 80, no `ports` (Nginx Proxy Manager on a shared Docker network; `networks` block left commented, NPM network name unknown), uid 1000, `TZ=Europe/Madrid`, `PYTHONUNBUFFERED=1`, `CARPETA_PDFS=/app/pdfs` in the named volume `operaciones_pdfs` (explicit `name:`; chmod 777 in the image so uid 1000 can write), SMTP config as compose secret `operaciones_env` (`file: ./.env`; in Portainer an absolute host path; must be readable by uid 1000).
- Git: the user creates the GitHub repo and pushes the changes; do not commit or push unless asked. Gitignored: `.venv`, `.env`, `*.pdf`, `pdfs/`, `*_salidas.json`.

Docs: `README.md` (landing page: exercises with `docs/multiplicaciones.png` / `docs/divisiones.png` renders regenerated by hand, install, usage, web, Docker/NPM, customizing, adding an exercise, third-party licenses, Fortnite/Epic non-affiliation note) and `AYUDA.md` (per-file/function/constant reference in Spanish). Keep both in sync when changing functions, constants, commands or setup.
